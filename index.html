Q · 01

Make a Note on DBMS Classification

A Database Management System (DBMS) is software that enables users to create, store, retrieve, and manage data in a structured way. DBMS can be classified on several bases:

▸ Classification Based on Data Model

🔗

Hierarchical

Data organized in a tree-like parent-child structure. Ex: IBM IMS

🕸

Network

Data organized in a graph — each record can have multiple parents. Ex: IDMS

📊

Relational

Data stored in tables (relations) with rows & columns. Ex: MySQL, Oracle

🧩

Object-Oriented

Data represented as objects like in OOP. Ex: ObjectDB

📄

NoSQL

Non-tabular data — document, key-value, graph stores. Ex: MongoDB, Redis

▸ Classification Based on Number of Users

👤

Single-User

Only one user accesses DB at a time. Ex: MS Access

👥

Multi-User

Multiple users access simultaneously. Ex: Oracle, SQL Server

▸ Classification Based on Distribution

🖥

Centralized

All data on a single central server.

🌐

Distributed

Data distributed across multiple physical locations.

☁️

Cloud DBMS

Hosted on cloud infrastructure. Ex: Amazon RDS, Firebase

▸ Classification Based on Cost / Access

🔓

Open Source

Freely available. Ex: MySQL, PostgreSQL, SQLite

💼

Commercial

Licensed software. Ex: Oracle DB, MS SQL Server

💡 Key Takeaway: The most widely used classification is by Data Model — especially the Relational DBMS (RDBMS) which forms the basis of almost all modern database systems.
Q · 02

Define Data Model

📖 Definition: A Data Model is a collection of conceptual tools used to describe data, data relationships, data semantics, and consistency constraints. It provides an abstract representation of how data is organized, stored, and manipulated in a database.

A Data Model answers three core questions:

🏗

Structure

How is data organized? (tables, trees, graphs)

⚙️

Operations

What can be done with data? (CRUD: Create, Read, Update, Delete)

📏

Constraints

What rules must data follow? (Primary key, Not Null, etc.)

▸ Types of Data Models

🗺

Conceptual

High-level, user-understandable. Ex: ER Model

🔗

Logical

Defines structure without physical details. Ex: Relational Model

💾

Physical

Describes how data is stored on hardware.

🧱

Hierarchical

Tree structure: one parent, many children.

🕸

Network

Graph structure: many-to-many relationships.

📋

Relational

2D tables with rows & columns. Most popular.

Q · 03

What is Entity and Entity Set?

▸ Entity

📖 An Entity is any real-world object or thing that has an independent existence and can be distinctly identified. It can be a physical object, a concept, or an event about which data is stored.

Examples: A specific Student (Sudarshan, Roll No. 21), a particular Book (DBMS by Navathe), a specific Employee (Emp ID: E101).

▸ Attributes of an Entity

Each entity has properties called attributes. For example, a STUDENT entity has: Name, Roll No., Age, Department.

▸ Entity Set

📖 An Entity Set is a collection of all entities of the same type that share the same properties or attributes. It is the set/group of similar entities.

Example: All students enrolled in a college form an entity set called STUDENT. All employees in a company form the EMPLOYEE entity set.

Q · 05

What are Relationship Types — Degree and Cardinality

📖 A Relationship is an association among two or more entities. Relationships have a degree (how many entities participate) and a cardinality ratio (how many instances are involved).

▸ Degree of a Relationship

1

Unary (Degree 1)

Relationship between instances of the same entity set.

Ex: An Employee manages another Employee.

2

Binary (Degree 2)

Relationship between two entity sets. Most common type.

Ex: Student enrolls in Course.

3

Ternary (Degree 3)

Relationship among three entity sets simultaneously.

Ex: Doctor prescribes Drug to Patient.

▸ Cardinality Ratios (for Binary Relationships)

1️⃣

One-to-One (1:1)

One entity in A relates to only one entity in B.
Ex: Person ↔ Passport

1️⃣➡️🔢

One-to-Many (1:N)

One entity in A relates to many in B.
Ex: Teacher → Students

🔢↔️🔢

Many-to-Many (M:N)

Many entities in A relate to many in B.
Ex: Students ↔ Courses

▸ Participation Constraints

Total Participation: Every entity in the set must participate in at least one relationship (shown as double line ══).

Partial Participation: Some entities may not participate in any relationship (shown as single line ─).

Q · 06

Composite Attribute and Derived Attribute — with Examples

Attributes describe properties of entities. There are several types — let's focus on the two asked:

🧩

Composite Attribute

An attribute that can be divided into smaller sub-attributes, each representing a basic attribute with independent meaning.

Example: Full_Name = First_Name + Middle_Name + Last_Name
Another: Address = Street + City + State + PIN

In ER diagram: The composite attribute is shown as an oval connected to smaller ovals (sub-attributes).

🔮

Derived Attribute

An attribute whose value is derived (calculated) from another attribute or set of attributes already in the database. It is not physically stored.

Example: Age can be derived from Date_of_Birth and current date.
Another: Total_Salary = Basic_Pay + HRA + DA
Another: Experience derived from Joining_Date

In ER diagram: Derived attributes are shown with a dashed oval.

▸ All Attribute Types — Quick Reference

⚫

Simple

Cannot be divided further. Ex: Emp_ID, Age

🧩

Composite

Can be split into sub-parts. Ex: Address, Name

🔮

Derived

Calculated from other attributes. Ex: Age, Experience

🔢

Multi-valued

Can hold multiple values. Ex: Phone_Numbers, Skills

🔑

Key

Uniquely identifies an entity. Ex: Emp_ID, Roll_No

∅

Null

Can have no value (optional). Ex: Middle_Name

Q · 08

DBMS Languages — DDL, DML, DCL, TCL

📖 SQL (Structured Query Language) is divided into four major sub-languages based on their purpose: DDL, DML, DCL, and TCL.
DDL

Data Definition Language

Defines and manages the structure of the database — creates, modifies, or removes schema objects. Changes are auto-committed.

CREATE ALTER DROP TRUNCATE RENAME
DML

Data Manipulation Language

Manipulates data within tables — insert, update, delete, or retrieve records. Changes can be rolled back.

SELECT INSERT UPDATE DELETE
DCL

Data Control Language

Controls access and permissions to the database. Used by admins to grant or revoke user privileges.

GRANT REVOKE
TCL

Transaction Control Language

Manages transactions — ensures data consistency by controlling save points and rollbacks.

COMMIT ROLLBACK SAVEPOINT

▸ Combined SQL Example — Student Database

-- ① DDL: Create the table structure CREATE TABLE Students ( Student_ID INT PRIMARY KEY, Name VARCHAR(50) NOT NULL, Department VARCHAR(30), Marks DECIMAL(5,2) ); -- ② DML: Insert data into the table INSERT INTO Students VALUES (1, 'Sudarshan', 'CSE', 88.5), (2, 'Priya', 'IT', 92.0), (3, 'Arjun', 'ECE', 76.3); -- ③ DML: Update a record UPDATE Students SET Marks = 95.0 WHERE Name = 'Sudarshan'; -- ④ TCL: Commit the transaction (save changes) COMMIT; -- ⑤ DML: Delete a record DELETE FROM Students WHERE Student_ID = 3; -- ⑥ TCL: Rollback if something goes wrong ROLLBACK; -- ⑦ DCL: Grant SELECT permission to a user GRANT SELECT ON Students TO 'teacher_user'; -- ⑧ DDL: Alter table — add a new column ALTER TABLE Students ADD COLUMN Email VARCHAR(100); -- ⑨ DML: Select / Retrieve data SELECT Name, Marks FROM Students WHERE Marks > 80 ORDER BY Marks DESC; -- ⑩ DDL: Drop table (permanent delete) DROP TABLE Students;
